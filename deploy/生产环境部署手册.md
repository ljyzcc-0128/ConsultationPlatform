# 储能资讯平台 — 生产环境部署手册

> 服务器：Rocky Linux 9.3（内网 GitLab：`http://gitlab.jinkosolar.com/ai-jk/es_information_platform`）
> 部署形态：Docker Compose 全容器化（方案 A）+ GitLab CI/CD 流水线自动构建发布
> 文档版本：2026-11-11 v1.0

---

## 1. 架构总览

```
GitLab (gitlab.jinkosolar.com)
   │  push dev/main 触发流水线
   ▼
Rocky 服务器 (10.21.13.77)
├── rocky-docker-runner (docker executor, 挂载 docker.sock)
│      build/test → package:images (构建 local/* 镜像) → deploy:local (手动)
└── Docker Compose (/opt/ums, 网络 ums-net)
       ├── ums-mysql        127.0.0.1:3306  (初始化: 01-users.sql + 02-tables_xxl_job.sql + Flyway)
       ├── ums-rabbitmq     127.0.0.1:5672 / 15672 对外
       ├── ums-xxl-job      8088→8080       (定时任务调度)
       ├── ums-main-java    8080 / 9999     (Spring Boot, Flyway 建表, prod profile)
       ├── ums-crawler-py   8100            (Playwright 爬虫, MQ 消费)
       └── ums-web          80              (Nginx, 反代 /api→8080, /crawler→8100)
```

数据链路：xxl-job 定时触发 → ums-main 调爬虫(`UMS_CRAWLER_URL`) → 爬虫抓信源 → RabbitMQ → ums-main 消费入库(cp_news) → AI 加工(智谱 GLM) → 前端展示。

## 3. 阶段一：服务器基础环境

```bash
# Docker 安装（离线包安装见附录 A；在线安装如下）
sudo dnf install -y dnf-plugins-core
sudo dnf config-manager --add-repo https://download.docker.com/linux/rhel/docker-ce.repo
sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker

# 国内镜像加速
sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
{ "registry-mirrors": ["https://docker.m.daocloud.io"] }
EOF
sudo systemctl restart docker

# GitLab Runner
curl -L "https://packages.gitlab.com/install/repositories/runner/gitlab-runner/script.rpm.sh" | sudo bash
sudo dnf install -y gitlab-runner
sudo systemctl enable --now gitlab-runner

# 验证
docker version && docker compose version && gitlab-runner --version
```

## 4. 阶段二：部署目录与配置文件

### 4.1 目录结构

```bash
sudo mkdir -p /opt/ums/{mysql/data,mysql/init,rabbitmq/data,nginx/conf,app}
```

### 4.2 上传仓库内文件到服务器

| 仓库文件 | 服务器路径 |
|---|---|
| `deploy/mysql-init/01-users.sql` | `/opt/ums/mysql/init/01-users.sql` |
| `deploy/mysql-init/02-tables_xxl_job.sql` | `/opt/ums/mysql/init/02-tables_xxl_job.sql` |
| 原生部署遗留的 `/opt/ums/app/app.env` | 保留原位（compose 通过 env_file 继承） |

> **注意**：`mysql/data` 必须为空，MySQL 容器首次启动才会执行 init 脚本。

### 4.3 密钥文件 `/opt/ums/.env`（chmod 600）

```bash
sudo tee /opt/ums/.env > /dev/null <<'EOF'
MYSQL_ROOT_PASSWORD=<root强密码>
RABBITMQ_DEFAULT_USER=<MQ用户，与app.env中UMS_MQ_USER一致>
RABBITMQ_DEFAULT_PASS=<MQ密码>
EOF
sudo chmod 600 /opt/ums/.env
```

### 4.4 `/opt/ums/docker-compose.yml`

完整内容见附录 B（要点：ums-main-java / ums-crawler-py 挂 `env_file: /opt/ums/app/app.env` 继承 SSO/JWT/AI 等真实配置；`environment:` 块覆盖容器网络地址：`UMS_MYSQL_HOST=mysql`、`UMS_MQ_HOST=rabbitmq`、`UMS_CRAWLER_URL=http://ums-crawler-py:8100`、`XXL_JOB_ADMIN_ADDRESSES=http://xxl-job-admin:8080/xxl-job-admin`；AI key 在 compose 中替换为真实智谱 key 或加入 .env 引用）。

### 4.5 `/opt/ums/nginx/conf/default.conf`

```nginx
server {
    listen 80;
    server_name _;
    client_max_body_size 20m;

    location / {
        root /usr/share/nginx/html;
        index index.html;
        try_files $uri $uri/ /index.html;
    }
    location /api/ {
        proxy_pass http://ums-main-java:8080/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
    location /crawler/ {
        proxy_pass http://ums-crawler-py:8100/;
        proxy_set_header Host $host;
    }
}
```

### 4.6 防火墙

```bash
sudo firewall-cmd --zone=public --add-port=80/tcp --permanent
sudo firewall-cmd --zone=public --add-port=15672/tcp --permanent   # RabbitMQ 管理台（原环境对外）
sudo firewall-cmd --reload
```

## 5. 阶段三：GitLab Runner 注册

> 必须用**项目级 registration token**（项目 → Settings → CI/CD → Runners 页面获取），不能用实例级 token，否则 runner 不会出现在项目里、任务被别的机器抢走。

```bash
sudo gitlab-runner register \
  --url http://gitlab.jinkosolar.com \
  --registration-token <项目注册token> \
  --executor docker \
  --description rocky-docker-runner \
  --docker-image alpine:latest \
  --docker-pull-policy if-not-present \
  --docker-volumes "/cache" \
  --docker-volumes "/var/run/docker.sock:/var/run/docker.sock" \
  --docker-volumes "/opt/ums:/opt/ums"
```

然后编辑 `/etc/gitlab-runner/config.toml`，在 `[[runners]]` 段内加 `run_untaged = true`（本版本 register 不支持该参数，须手工补）：

```toml
[[runners]]
  name = "rocky-docker-runner"
  executor = "docker"
  run_untaged = true
  [runners.docker]
    pull_policy = "if-not-present"
    volumes = ["/cache", "/var/run/docker.sock:/var/run/docker.sock", "/opt/ums:/opt/ums"]
```

```bash
sudo systemctl restart gitlab-runner
```

**验证**：GitLab 项目 Settings → CI/CD → Runners 出现 `rocky-docker-runner`（active）。
**禁绝抢任务**：其他机器（如开发 Mac）的 runner 一律 unregister。

## 6. 阶段四：流水线发布

1. 本地推送：`git push neworigin dev`
2. 流水线自动执行：`backend:build-test` / `frontend:build-test` / `crawler:test`（changes 触发）→ `package:images`（dev/main 自动，构建 `local/ums-web|ums-main-java|ums-crawler-py:latest` 到服务器 Docker）
3. `package:images` 绿勾后，手动点击 `deploy:local` 播放按钮 → `docker compose up -d --force-recreate` 三个应用容器
4. 首次部署：MySQL/RabbitMQ/xxl-job 容器随 compose 首次拉起，init 脚本建号建库，Flyway 执行 V1..Vn 迁移

## 7. 阶段五：启动后配置（xxl_job 为新库，必须手工配置）

1. 登录 `http://10.21.13.77:8088/xxl-job-admin`（默认 admin/123456）→ **立即改密码**
2. 执行器管理 → 新建执行器（AppName 与 Java 端一致，等待自动注册出现）
3. **重建全部定时任务**（老库配置不会迁移）：
   - `crawlScheduledJob`（资讯信源总采集）：Cron `0 0 6 * * ?` 每日 06:00
   - SMM 日度/周度/月度任务：Cron 按官网更新频率；**凭据未配置前保持停用**
4. 平台首次访问 `http://10.21.13.77` → 注册账号 → 重建关注订阅规则（新库用户数据为空）

## 8. 阶段六：端到端验收清单

```bash
# 1. 六容器全部 Up
docker compose -f /opt/ums/docker-compose.yml ps
# 2. Flyway 迁移全部执行
docker logs ums-main-java 2>&1 | grep -i flyway
# 3. 信源 19 条
docker exec ums-mysql mysql -uums_app -p'***' cp_news -e "SELECT COUNT(*) FROM cp_source;"
# 4. 手动触发一次抓取（信源管理页"触发抓取"按钮，选国内信源如 ESCN）
# 5. 链路日志
docker logs ums-crawler-py --tail 50
docker logs ums-main-java --tail 50
# 6. 入库 + AI 加工
docker exec ums-mysql mysql -uums_app -p'***' cp_news \
  -e "SELECT COUNT(*) FROM cp_news; SELECT COUNT(*) FROM cp_news WHERE summary IS NOT NULL;"
# 7. 浏览器访问 http://10.21.13.77 验证情报中心有数据
```

全部通过后，xxl-job 总任务次日 06:00 自动执行；观察一轮无报错即部署完成。

## 9. 回滚与故障排查

| 现象 | 排查 |
|---|---|
| 任务一直 pending | runner 未 run_untaged / 被 Mac runner 抢走 → 检查任务页右上 Runner 名 |
| 拉镜像超时 | `docker info` 看 Registry Mirrors 是否含 daocloud；预拉基础镜像 |
| Java 容器起不来 | `docker logs ums-main-java`；常见：UMS_AI_API_KEY 占位符未替换、MySQL 未 healthy |
| Flyway 校验失败 | init 目录残留旧数据 → `rm -rf mysql/data/*` 重新 init |
| 爬虫 Playwright 报浏览器缺失 | requirements 与基础镜像版本必须同为 1.40.0 |
| 海外信源抓取失败 | 网管出口未开通 → 走 HTTP_PROXY |
| **回滚** | `git revert` + 重新 push 跑流水线；或 `docker compose down` 后用旧镜像 tag 手工 up |

## 附录 A：完全离线安装包

当服务器无外网时，使用《docker-offline-rpms.tar.gz》（Docker 全家桶 10 RPM）与《gitlab-packages.tar.gz》（gitlab-runner + helper-images + git 及依赖 74 RPM）离线安装：

```bash
tar -xzvf docker-offline-rpms.tar.gz && cd docker-offline-rpms
sudo dnf install ./*.rpm --disablerepo='*'
sudo systemctl enable --now docker
tar -xzvf ../gitlab-packages.tar.gz && cd gitlab-packages
sudo dnf install ./*.rpm --disablerepo='*'
sudo systemctl enable --now gitlab-runner
```
